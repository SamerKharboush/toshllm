# Firellama CONTEXT

Glossary for the max-perf effort. Precision here prevents wrong fixes.

## Split VRAM budget

The two D700s share nothing: no unified pool, no Infinity Fabric link
(peer group 0, measured via probe). Never say "12GB VRAM" bare. Use:

- **Split budget (~12GB)**: total model capacity across both cards under
  layer split. Each card holds different layers.
- **Per-device ceiling (6GB)**: no single card holds more than its own VRAM.
- **Per-buffer ceiling (3.5GB)**: `maxBufferLength` per D700, measured.
  A single buffer larger than this aborts (`:1154 multi buffers`),
  regardless of total budget.

## Split modes

- **Layer split**: different layers per GPU. The fit path for models over
  6GB (Qwen3-14B-Q4_K_M at 8.38GB loads and runs). No speedup at 4B scale
  (78.45 vs 78.70 pp). Needs `GGML_METAL_DEVICES=2` count var;
  `GGML_METAL_DEVICE_LIST=0,1` alone leaves MTL1 closed on this path.
- **Tensor split**: same layers sharded across GPUs. The speed path:
  4B pp 78.7 single vs 141.7 none vs 153.3 events. `TOSH_MGPU_EVENTS`
  wins prefill (+8%); `TOSH_MGPU_PEER` is inert on non-bridged cards.

## Thread rule

Threads default to physical cores (12), capped at physical. 24 SMT threads
collapse decode (tg 17.4 to 11.7, measured 2026-09-30). Never logical count.

## pp vs tg

- **pp (prompt processing)**: GPU matmul bound. Moves with split mode
  and sync flags.
- **tg (token generation)**: wave64 CPU decode/BLAS bound on GCN.
  Flat across sync configs (17.5). Moves with thread count and ISA.

## Acceptance models

- Qwen3-14B-Q4_K_M (8.4GB): runs layer-split; target is best measured
  config, tensor-or-layer. Measured 2026-10-02: layer split 21.25 pp512 /
  5.10 tg64 (14B needs both cards; 8.38GiB will not fit one 6GB card).
  Tensor split 41.40-43.09 pp512 / 8.55-8.56 tg64.
- Ternary-Bonsai-27B: loads and generates coherently. Measured
  2026-10-02 on a **layer split with events off**: 11.54 pp512 / 6.22 tg64,
  end-to-end chat coherent at 6.16 tok/s. Not Dynamic MoE — arch
  `qwen35` has no expert tensors, so the planner is inert on it.
- 35B-class: fog. 27B passed; nothing above it has been measured.

## Split flags that must be earned

Both multi-GPU hand-off flags are now gated on topology or split mode,
because measurement contradicted what their comments claimed.

- `TOSH_MGPU_PEER` — only when `peerGroups` shows a group of two or more. On
  this non-bridged pair the isolated effect was pp 0.00 / tg 0.00.
- `TOSH_MGPU_EVENTS` — only on a tensor split. It **was** a hard fault on a
  layer split above a model-dependent prompt length (14B at p>=257, 27B at
  p>=129), fixed in patch 0126; but it is still a wash on a layer split
  (14B p=512: 21.24 with, 21.29 without), so it stays gated off there.

A layer split has few cross-device hand-offs, so the pair could sit on one
unsignalled event. A tensor split makes hundreds and stays saturated.

## Ticket vocabulary

Fork issues are disabled, so tickets are files under `.scratch/<effort>/`. Names:

- **Effort**: one directory holding a map plus its tickets.
- **Map**: `.scratch/<effort>/map.md` — destination, notes, decisions, fog.
- **Ticket**: `.scratch/<effort>/issues/<NN>-<slug>.md`, with `Type:` and
  `Status:` lines.
- **Task ticket**: carries work through to landed and measured.
- **Research ticket**: resolves at findings — drop point or answer plus a
  proposed fix. Implementation moves to a new task ticket.
- **Frontier**: open, unblocked, unclaimed tickets. Lowest number wins.

## GCN codegen trust

AMD GCN/Tahiti miscompiles some integer and float expressions in ways that
pass every static check. Treat a GCN-only numeric failure as a codegen bug
before a numerical one, and prefer a different expression form over
compensating in arithmetic:

- **Parity tests**: `x % 2 != 0` on an `int` from a kernel argument struct
  can report odd for an even value. Express the same predicate as a
  multiply-compare (`half * 2 < dim`), which GCN compiles correctly.
- **Precise arithmetic is not a fix**: `precise::` intrinsics were applied to
  the timestep kernel and the failure persisted, because it was never
  precision. Rule it out by measurement, not by argument.

## Red loop

One command, red-capable, seconds, agent-runnable:

```sh
./vendor/llama.cpp/build-static/bin/test-backend-ops -b MTL0 -o TIMESTEP_EMBEDDING
```

The unfiltered suite (`test-backend-ops -b MTL0`, ~10 min, 10701 cases) is the
regression gate, not the red loop.

**Probe before theory**: byte-level `printf` instrumentation in
`tests/test-backend-ops.cpp` (temporary, revert after) turned a
non-deterministic 1e-3 error into an exact single-element, always-zero
signature in one run. The vendored test file is regenerated by
`build-engines.sh`; verify it byte-identical to its backup afterwards.

## Resolved defects

**`timestep_embedding` Metal kernel on GCN** (fixed, patch 0125). GCN
miscompiles `args.dim % 2 != 0` and took the odd-dim branch for an even
`dim`, writing `embed_data[2*half_]` one whole row past the row the
threadgroup owned: every row zeroed its successor's first element and the
last row wrote past the end of `dst`. Fix is the same predicate as
`half_ * 2 < args.dim`. Diffusion/image path only; the LLM text path was
never affected.

**Menu-bar LAN toggle dropped the setting** (fixed, `ToshLLMApp.swift`).
An added server always has a pinned list, so `effectiveSettings()` reads
only pinned fields; the toggle wrote the profile value without pinning it,
and the engine bound `127.0.0.1` while the switch read on.

**`--fit` abort was silent** (fixed, `ServerController.fitNote`). The
engine logged `not fitting params to free device memory` and continued; the
app never surfaced it. Now shown on the server card.

**`GGML_METAL_DEVICE_LIST` was blamed for a single GPU** (no defect). An
earlier 4B layer measurement read as "layer ignores DEVICE_LIST" because a
4B layer split buys nothing by definition. At 14B, `DEVICE_LIST=0,1` alone
registers MTL0+MTL1 and loads a model that will not fit one card. The app
seam at `Server.swift:644-658` was already correct. The real gap remains:
a split that silently lands on one GPU gives the user no signal.

**`TOSH_MGPU_EVENTS` deadlocked a layer split** (fixed, patch 0126). The
destination's wait was a GPU-side `waitForEvent` encoded into a new command
buffer, so the copy landed behind whatever the destination already had
queued. Now a bounded host-side wait, with drain-and-complete recovery so a
stall cannot wedge the next hand-off.

**`NSMakeRange` length was an end offset** (fixed, patch 0126). The memset
tensor path filled `offs + size` bytes from `offs`, overrunning by `offs`.

**The 27B `qwen35` SSM reshape cannot be tensor-split** (diagnosed, not
fixed). `ne[0]=6144` does not divide `ne[0]=9216`. The abort now names the op
and dimensions. Fixing it needs a numerical A/B this hardware cannot host.

## Exposure proof

Three levels, and they are not interchangeable:

- **Loopback curl** — proves the engine is up. Says nothing about exposure.
- **Self over a non-loopback address** — proves the bind and the
  reachable-interface path. This is where an `--host` bug lives, so it is
  the level worth having.
- **Second host** — proves another machine's firewall and routing. Only this
  is a real network test.

LAN exposure is closed at the second level. A second-host test is still owed.

## Memset range

`ggml_backend_tensor_memset(tensor, value, offset, size)` fills `size` bytes
from `offset`. Nothing in a text forward pass calls it at a non-zero offset,
so the backend suite cannot catch a bad range — only a direct test can.

## Metal kernel precompile

`kernels/` ships precompiled `.metallib` files when an Xcode `metal`
compiler is present at build time. Without one the engine compiles its own
kernels at first launch: about 143 s, once. Functionally identical.

Not the same thing as a bundle lacking engine binaries. The engines are
always bundled; only the optional precompiled kernels are skipped.

## What a fork can and cannot do

- Actions on a fork can silently not run on `push` while `workflow_dispatch`
  works. Probe it with a commit that touches a `paths`-filtered file before
  assuming a workflow is broken.
- Notarization needs an Apple Developer identity in the fork's secrets. No
  identity means the DMG is ad-hoc and macOS quarantines it.
- `xcodebuild -downloadComponent` needs an Xcode app, not just Command Line
  Tools. `softwareupdate` does not offer the Metal toolchain.

## Tensor-split refusal

Exit code **86**, ours, means "this model has no two-way tensor split". It is
deliberately not a signal: SIGABRT (134) is a crash, 86 is a setting.

The app treats it as a retryable condition — relaunch with `--split-mode layer`
once, and say so. The user's split-mode **setting is not rewritten**, so a model
that does support tensor split is not permanently downgraded.

## Fork scope: AMD GCN on Intel Macs

Every engine patch in this fork is an AMD GCN workaround: `is_wave64`,
`needs_aligned_loads`, `TOSH_FA_AMD`, the `amdgpu_gfx600` mat-vec path. An Apple
GPU probes a 32-wide SIMD group, so `is_wave64` is false and every one of those
paths is off by construction.

Consequence: **these fixes carry no weight on Apple Silicon**, and the bundle is
x86_64-only. For an Apple Silicon machine, upstream's build is the right answer.

**Settled 2026-10-03: the fork targets Intel x86_64 only.** No arm64 slice, no Apple Silicon
support. Notarization is deferred to a future rebrand. So the "AMD GCN on Intel Macs" section
above is not a temporary limitation to be lifted — it is the scope.

`docs/agents/apple-silicon-handoff.md` is the spec for an assistant opening this repo cold.
