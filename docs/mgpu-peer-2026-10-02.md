# mgpuPeer on a non-bridged pair (2026-10-02)

Hardware: 2x FirePro D700 (Tahiti, GCN 1.0), PCIe, **peer group 0, not bridged**.
Engine 0.87.11 + patch 0114, 12 threads (physical), `-fa 1`, `GGML_METAL_CONCURRENCY_DISABLE=1`,
`GGML_METAL_DEVICE_LIST=0,1`, model Qwen3-14B-Q4_K_M (8.38 GiB), `-p 512 -n 64 -r 2`,
`--split-mode tensor`.

## Result

| config | pp512 | tg64 |
| --- | --- | --- |
| no flags | 41.40 | 8.55 |
| `TOSH_MGPU_PEER=1` + `TOSH_MGPU_EVENTS=1` | 43.07 | 8.55 |
| `TOSH_MGPU_EVENTS=1` only | 43.08 | 8.54 |

Repeated twice each; the no-flag and events-only rows reproduced to 0.01.

## What it shows

The apparent +4% on prefill is **`TOSH_MGPU_EVENTS`, not peer**. With events held on, peer
alone moved pp by 0.00 and tg by 0.00. The first two rows differ only because the second adds
both flags.

So on a pair with no fabric link, `TOSH_MGPU_PEER` buys nothing measurable while the flag was
defaulted to true. That is the opposite of the comment it shipped with ("Worth 16% of the
prefill"), which describes a bridged pair.

## Change

`TOSH_MGPU_PEER` is now gated on `ServerSettings.peerBridgeAvailable`, which asks
`HardwareInfo.peerGroups` for any group of two or more. A card with no bridge reports group 0
and `peerGroups` drops those, so an unbridged pair no longer sets the flag. The user toggle is
untouched: someone on a bridged pair still gets it, and someone who wants to force the
experiment can still set the env by hand.

Earlier 4B numbers in `docs/bench-baseline-2026-09-30.md` (141.71 none / 141.85 peer) already
showed peer as inert at small scale; this extends that to 14B and separates it from events.
